# 0008. CI

Status: accepted, 2026-09-24

## Context

CI called reusable workflows from another repository's `main` branch, so a change there could break or silently weaken this repo's checks. The prek job only annotated failures. The converge test ran one role list, not what a real machine gets.

## Decision

- Every job is defined in this repository; actions are pinned by SHA.
- prek (including yamllint, markdownlint, shellcheck and ansible-lint) fails the build.
- Each supported release converges each profile in a clean container, twice. The second run must report `changed=0`.
- The same runs happen weekly, to catch upstream rot: a moved apt suite, a renamed release asset, a new linter release.
- One aggregate check, `CI OK`, is the required status.

## Consequences

- A broken upstream shows up as a red weekly run rather than on the next real machine.
- There is no failure notification beyond GitHub's own; a red scheduled run has to be noticed.
